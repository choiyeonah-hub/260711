# 우리집 약장 (MVP 프로토타입)

부모님 가정의 의약품을 **정리하고, 가족이 함께 관리하며, 공식 의약품 안전정보를 쉽게 확인**하도록 돕는 모바일 웹앱(PWA)입니다.
진단·처방·복약지도·개인별 약 추천·용량 결정은 하지 않습니다. 안전정보는 공식 출처 데이터를 옮겨 보여주기만 합니다.

방문 흐름: 약 수집 → 상비약/처방약 구분 → 분류 → 유효기간 확인 → 수납·라벨링 → 사진 촬영·제품 확인·등록 → 가족 연결·다음 진료/처방 예정일 → 우리집 준비 체크 → 약장 안전확인 → 약사 확인 목록 → 자녀와 공유

## 실행 방법

```bash
npm install
npm run dev -- --host     # 같은 와이파이의 아이폰에서 http://<PC IP>:5173 접속
npm run build && npm run preview -- --host   # 배포본과 동일하게 확인
```

- 아이폰 실사용: HTTPS 주소(예: Vercel 배포)로 열고 Safari **공유 → 홈 화면에 추가** 하면 앱처럼 실행됩니다.
- 데이터는 그 기기 브라우저의 IndexedDB에 저장됩니다 (새로고침해도 유지, 서버 없음).
- 사진 AI 인식(선택): `.env.example` → `.env.local` 복사 후 `ANTHROPIC_API_KEY` 입력. Vercel은 프로젝트 환경변수에 같은 이름으로 등록. 키가 없으면 기기 내 OCR로 자동 동작합니다.

## 배포 (Vercel)

- `main`에 푸시하면 Vercel이 `vercel.json` 설정(Vite 빌드 → `dist`)으로 자동 배포
- AI 사진 인식: Vercel → Project → Settings → Environment Variables 에 `ANTHROPIC_API_KEY` 등록 후 **Redeploy** (키는 https://console.anthropic.com 에서 발급, 사용 한도 설정 권장)
- 키가 없거나 만료되면 앱은 자동으로 기기 OCR로 동작 (등록 흐름은 막히지 않음)

### Opus → Haiku 인식률 비교 절차
1. 첫 방문: `RECOGNIZE_MODEL` 비워둠(기본 `claude-opus-5-5`) → 정리 완료 화면의 **인식 엔진 · 사진인식 성공**이 기준값
2. 다음 방문 전: `RECOGNIZE_MODEL=claude-haiku-4-5` 설정 후 Redeploy
3. 설정 → 정리 작업 기록에서 세션별 엔진·성공률·작업시간 비교

## 구현된 기능

- **품목 유형 3종**: 의약품(MEDICINE) / 영양제·건강기능식품(SUPPLEMENT) / 의료용품(MEDICAL_SUPPLY)
  - 등록 첫 단계 "무엇을 등록할까요?"에서 선택. 의약품은 기존 사진 등록 흐름, 영양제·의료용품은 같은 폼 + 사진으로 제품명·기한 읽기(확인 후 적용)
  - 영양제: 주요 성분, 섭취방법·1일 섭취량(제품 표시 그대로), 소비기한/유통기한. 분류는 의약품 12분류와 별도(비타민·미네랄/오메가3/유산균/눈 건강/관절·뼈/기타)
  - 의료용품: 체온계/밴드/드레싱/거즈/테이프/기타
  - 공식 안전정보 비교(안전확인)는 의약품만 대상. 영양제–의약품 상호작용은 구현하지 않음(검증된 데이터 확보 후 `SafetyInformation.scope`로 확장)
  - 홈: 유형이 2개 이상이면 "등록 품목 N" + "의약품 · 영양제 · 의료용품" 개수 / 약장: [전체·의약품·영양제·의료용품] 필터
  - 기존 데이터: productType 구값(PRESCRIPTION/OTC/HEALTH_SUPPLEMENT)을 자동 변환, 기존 의약품은 MEDICINE (백업 JSON 가져오기도 동일)

- 홈: 총 의약품 / 유효기간 임박(90일 이내) / 만료, 다가오는 진료·처방 일정(D-day), 가족별 약장 요약, 큰 검색창(이름·분류·위치·가족)
- **사진으로 약 등록 (기본)**: 촬영 → 글자 인식 → 제품 후보 선택 → 유효기간 "맞아요/수정" 확인 → 추천 분류 확인·위치 → **저장 후 📷 다음 약 촬영**(카메라 바로 열림)
  - 못 찾으면: 다시 촬영 / 제품명 검색 / 직접 입력. 유효기간 못 찾으면: 유효기간 부분만 다시 찍기 / 직접 입력 / 표시 없음
  - 인식 결과는 항상 사람이 고르고 확인한 뒤에만 저장. 매칭이 애매하면 "확인이 필요합니다" 표시
- 약 등록(직접 검색/입력): 필수(제품명·12분류·보관 위치) + 선택(사진·가족·유효기간·수량·메모·처방약·다음 진료/처방 예정일)
  - **저장 후 다음 약**: 가족·위치·카테고리를 다음 약에도 유지(📌 토글)
  - 유효기간 빠른 입력: `2708` → 2027.08, `20270815` → 2027.08.15 (월까지만 입력 시 말일 기준)
  - 최근 입력 + 제품 DB(mock) 자동완성, DB 제품 선택 시 분류 추천
- 약장 보기: 12분류 카드 + 보관 위치별 목록(위치마다 수납 방식 StorageType 지정: 12칸 서랍/4~6칸 수납함/바구니/파우치/기존 서랍/기타)
- **약 상세 · "이 약을 드실 때 알아두세요"**: 🔴 중요 안전정보 / 🟡 생활 속 주의사항(🍊음식·음료, ⏰복용 관련, 🚗일상생활) / 🔵 알아두면 좋은 정보(색 변화 등) + 출처 표시 + "식약처 공식 허가정보 · 허가된 용법·용량 보기" 링크
- **우리집 약장 안전확인**: 처방약+상비약 전체를 하나의 목록으로 비교 → 🔴/🟡/🔵 건수, 관련 약 표시, [공식정보 보기], [약사에게 확인할 목록에 추가]. 제품 미확인(UNVERIFIED) 약은 비교에서 제외하고 따로 표시
- **약사에게 확인할 목록**: 안전확인·준비 체크에서 추가 또는 직접 입력, 확인함 체크, 공유(공유 시트/복사), 인쇄·PDF
- **우리집 준비 체크**: 해열·진통, 감기·알레르기, 위장·장, 상처관리, 드레싱, 밴드·테이프(등록 약으로 자동 판단) + 화상 대응용품, 체온계(직접 체크). 상태 있음/준비되어 있지 않습니다/유효기간 지난 것만/확인 전. 제품 추천 없음
- 처방약: 가족 연결, 다음 진료/처방 예정일(입력값만), **현재 복용 여부**(복용 중/복용 안 함/확인 필요)
- 일정: 가족별 다음 진료/처방 예정일, 지난 예정일 표시(자동 추정 안 함)
- 알림센터(앱 내부): 유효기간 30일·7일·만료, 진료/처방 예정 7일 이내
- 약장 정리 모드: 방문 정리 순서 안내, 완료 시 처방/상비, 만료, 3개월 이내 만료, 확인 필요(제품 식별 불가·주인 불명확 처방약·복용 여부 확인 필요), 단계별 작업시간 입력(9단계), 사진/직접 등록 수, 사진 인식 성공, 만료 발견(등록한 만료약 + "만료약 폐기 +1" 카운터), 처방약 수, 수납 방식 기록 → 완료 요약
- 사업성 설문(8문항: 기존 앱 인지, 직접 등록 의향, 전문가 첫 정리 의향 포함) 저장, 설정에서 정리 기록·설문 결과 조회
- 여러 가정(어머니 집 / 시댁 등) 추가·전환, 가족 추가·수정·삭제
- 백업 내보내기/가져오기(JSON, 아이폰은 공유 시트), 샘플 데이터 전체 삭제/다시 넣기
- PWA(홈 화면 설치, 오프라인 실행)

## 사진 인식 구현 방식

```
촬영(input capture) → src/services/ocr  ──1순위── /api/recognize (서버, Claude 비전, 키는 환경변수)
                                       └─실패/미설정─ 기기 내 Tesseract.js (kor+eng, public/ocr 자체 호스팅)
            → src/services/medicineSearch (제품 후보 점수화, 오탈자 허용) → src/services/categoryMapper (12분류 제안)
            → src/lib/expiryExtract (기기 OCR 텍스트에서 사용기한 추출: EXP/사용기한 우선, 제조일자 제외)
```

- 서버 AI는 사진에 보이는 글자만 JSON으로 옮기도록 지시(추측 금지, 복용·효능 정보 생성 금지). 20초 타임아웃·오류 시 기기 OCR로 대체.
- 인식 성공 = 사진에서 나온 후보를 그대로 고른 경우. 검색/직접입력으로 넘어가면 실패로 집계.
- **예상 AI 비용 (추정, 2026-10 단가 기준)**: 사진 1장 ≈ 입력 2천 토큰 + 출력 수백 토큰
  - 기본 `claude-opus-5-5`($4/$20 per 1M): 장당 약 $0.015~0.02 → 한 집 50개 약 $1 (약 1,400원)
  - `RECOGNIZE_MODEL=claude-haiku-4-5`($1/$5): 장당 약 $0.003~0.005 → 한 집 50개 약 $0.2
  - 기기 OCR: 무료 (첫 사용 시 약 9MB 다운로드 후 캐시)

### 현재 한계

- 제품 DB는 **mock 40개** (`src/services/mockMedicineDb.ts`). 목록에 없는 약은 "사진에서 읽은 이름 · 제품 DB에 없음"으로만 제안됨. 성분·제조사 값은 흐름 테스트용이며 의료정보로 쓰지 않음
- 기기 OCR(Tesseract)은 깨끗한 인쇄 글자는 읽지만 광택 포장·곡면(병·튜브)·작은 사용기한 각인에는 약함 → 현장에서는 AI 인식 권장
- 처방 약봉투·조제약은 DB 매칭 대상이 아님 → 직접 입력 사용
- 실제 아이폰 카메라·조명에서의 인식률/속도는 아직 미검증 (자동 테스트는 합성 이미지로 수행)

## 어머니 집 실제 테스트 체크리스트

**사진 등록 (이번 테스트 핵심)**
- 약 1개당 등록 시간 (목표 20~30초): 정리 종료 화면의 작업시간 ÷ 등록 수로 확인
- 사진 인식 성공률, 사진/직접 비율 → 종료 화면에 자동 기록
- 유효기간을 잘못 읽은 경우가 있었는지 (맞아요를 누르기 전 반드시 대조)
- 아이폰에서 "저장 후 📷 다음 약 촬영"을 누르면 카메라가 바로 열리는지
- AI 인식(키 설정)과 기기 OCR의 속도·정확도 차이

**안전정보·준비 체크**
- 실제 약 중 제품 확인(DB 선택)까지 되는 비율 → 안전확인 비교 대상 수
- 처방약 "누구 약인지 / 현재 복용 중인지"를 현장에서 확인할 수 있는지
- 약사 확인 목록을 실제로 약국에 가져갈 만한지, 부모님·자녀 반응
- 단계별 작업시간 입력이 번거롭지 않은지

**기본 흐름**

1. 첫 화면은 샘플 데이터 → 설정에서 **새 가정 추가(어머니 집)** 후 시작, 끝나면 샘플 삭제
2. 약 1개 등록에 걸리는 시간(목표 30초 이내), 유효기간 숫자 입력이 편한지
3. 처방약 등록 후 다음 약이 공용 상비약이면 **처방약 스위치가 유지되어 있는지 확인**(가족 유지 시 처방 정보도 유지됨)
4. 실제 약 봉투/처방전에서 다음 진료/처방 예정일을 확인할 수 있는지
5. 보관 위치 이름 규칙(예: "12칸 약장 3번")을 미리 정하면 검색이 쉬운지
6. 사진 촬영이 필요한지, 시간만 늘리는지
7. 작업시간·만료약 수·설문 결과 → 가격 책정 근거로 기록
8. 정리 후 **백업 내보내기**로 데이터 보관 (Safari 저장공간 정리로 인한 유실 대비, 홈 화면 추가 권장)
